OSSM system architecture

AdminWeb and GuestWeb are server-side Blazor hosts. One SignalR ControlService owns sessions, safety policy, ControlCore and every device write.

01   Deployment & connections 02   Control enforcement
01

Deployment & connections

Separately hostable web hosts call one ControlService. Remote access ends at GuestWeb; AdminWeb is deliberately unauthenticated and loopback-only.

02

Control enforcement

ControlService independently decides whether each hub command can reach the device; its controller checks again at execution.

What these boundaries do — and do not — guarantee

No accounts. AdminWeb is deliberately unauthenticated on loopback; AdminWeb/GuestWeb host keys and guest invitation/session capabilities are separate credentials. Creating a session link does not approve a guest, arm the device or start motion.

No direct guest control. GuestWeb cannot invoke operator methods or obtain device permissions. ControlService still constrains input from a compromised guest host that possesses a valid guest capability.

Physical overrides take precedence. Device parameter changes not explained by an owned command trigger lockout and Stop. Expected command readback is distinguished from external changes. The physical remote's detectability and stopping behavior must be demonstrated on the selected firmware.

Physical release remains gated. ControlService, OS or bridge failure can prevent a software Stop. Independent stopping on the selected hardware/firmware must be demonstrated; a completed write or readback is not physical stop confirmation. The 750 ms grant and tunable 1 s/3 s loss detection are not hardware qualification or real-time safety guarantees.
