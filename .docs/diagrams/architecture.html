Accepted MVP architecture / .NET 10

OssmSharp architecture

One computer, one device, one admin and one guest. Web.Api owns the device during web use. Cli is an alternative direct owner, without web policy.

Accepted target, not completed implementation. The OssmSharp rename, library separation, interactive CLI and independent simulator transport are planned. API and device lifetimes are intentionally shared. The machine-wide lock prevents cooperating CLI and API processes from owning the device concurrently.

Application & device path

Boxes are planned C# projects, with class libraries inside their consuming executable. Unboxed annotations describe internal code. Solid arrows show calls; dashed arrows show library references.

Standalone remote & development

The same project and arrow notation applies to Cli. Command dispatch is internal CLI code, not another project.

Interruption Requires Acknowledgement

Detected external changes, including physical remote input, latch interruption and inhibit pending motion. The local admin acknowledges into paused state through AdminWeb or an explicit CLI command. Only new explicit input may resume. Heuristics and completed writes do not prove physical stopping.

Migration Is Separate Work

The accepted design replaces the separate device-service proposal. No compatibility layer is required for this WIP. The migration plan includes repository instruction updates, project and namespace moves, independent simulator transport, provider packaging and verification before any completion claim.
